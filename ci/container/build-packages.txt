# 构建容器内所需的打包工具链。此前直接写在 image-build.yml 的 heredoc 里，
# 改动无法 review、无法复用，也无法在本地对照宿主是否齐备。
#
# 分组依据（不是按字母表）：
#   rpm 侧  rpm-build lorax createrepo_c xorriso isomd5sum —— 出 ISO 的最小集
#   编译侧  gcc gcc-c++ make flex bison bc —— 内核与 RPM 的共同前置
#   内核侧  dwarves cpio openssl-devel libtraceevent-devel elfutils-libelf-devel
#          clang llvm elfutils-devel libcap-devel numactl-devel systemtap-sdt-devel
#          —— pahole/BTF、模块签名、tracepoint、SDT 探针
#          kmod —— 固件预演（ci/gates/fw-preflight.sh）用 modinfo 从模块树
#          读 MODULE_FIRMWARE() 自报的请求名，与安装期 fw-flat.sh 同一条取法。
#          基础镜像是否自带 kmod 不作假设：缺它时预演报 fail=no-requests，
#          也就是把「工具不在」误读成「没有固件请求」，这条依赖必须显式声明。
#   脚本侧  git python3 python3-devel perl tar gzip rsync diffutils which
#          util-linux findutils ca-certificates —— run-image-ci.sh 的运行时依赖
#   取源侧  curl —— 配方以 `# spec-lint: source-url` 声明上游 tarball 时，
#          build-rpms.sh 用它下载并校验摘要
#   重建侧  ukui-control-center 的 BuildRequires（qt5/kf5/mate 一组）——
#          该包按 EPOL 源码重建，rpmbuild 在容器内按 rpmdb 解析 BR，缺一条
#          就只会报「Failed build dependencies」，因此逐条列在这里，让
#          工具链缓存一次预热、装配段严格离线。这些包只在 EPOL，容器镜像
#          自带的 repo 文件不含 EPOL，由 ci/gates 挂 distro/repo/
#          airymax-os.repo 补齐仓库表。
#          改动重建配方的 BR 必须同步本清单：两份不同步的唯一后果是装配段
#          构建失败，而失败信息指向配方，不指向这份清单。
